# Rebuilding Debian for a second N810

*11–17 November 2026. Offline comparison of the original N810 and boot tests on a second tablet.*

The original N810 had two Pocket trees, one in `/usr/local/share/n810-pocket` and another at `/home/nokia/pocket/current`. The home directory also held older Pocket releases, experimental Mesa libraries and the output from individual GPU tests. The graphics launcher selected a release in a third place, `/usr/local/lib/n810-graphics/releases/20261109-6970068`. Finding a newer library somewhere under home told us very little about what had drawn the desktop.

## Follow a service from boot to the files it opens

The APRS receive service shows how the tablet had grown. At boot, `/etc/rc.local` ran the scripts in `/etc/boot.d`. One of those started a supervisor as root, which in turn ran `/home/nokia/n810-aprs-feed.py` as the tablet user. The receiver imported modules alongside that script and used sockets and a station database. Copying the boot script alone would leave the new tablet with a service it could start and no receiver to run.

We followed those paths on a read-only copy of the original filesystems and compared them with the November 12 installer image. Of the Debian packages the two systems shared, only one differed in version. The harder work was accounting for files we'd put there ourselves. For graphics that meant identifying the launcher, Mesa library and matching kernel module. For maps it meant finding which pack and elevation files the reader opened. The old releases and trial outputs stayed in the backup.

The saved filesystems did not include the kernel flashed into the tablet. For the keyboard investigation we recovered the original kernel's source and compiler, built it with the root-device change needed by the second N810, and checked the running kernel's build identity after boot. The LM8323 keyboard controller still failed to acknowledge reads on its I²C bus. Its interrupt count stayed at zero. The later keyboard patches could be set aside as an explanation for that result. The cause of the failure remained open.

## Boot either Debian root with the same kernel

The SD installation puts two Debian root filesystems on one card. Early in boot, the flashed kernel runs a small selector that mounts the chosen root and hands control to its init process. A trial slot can be confirmed after Pocket starts. Maps and other persistent data occupy a separate partition, so replacing a root leaves those files in place.

On November 17 we used both roots during the audio repair. Slot B booted and passed the graphics check. After confirming B, we booted A, ran Pocket there, and updated the audio and launcher files on the inactive B partition. Both slots then contained the same checked files.
