# Which Pocket was the first N810 actually running?

*11–17 November 2026. Reconstructing the original installation and booting a second Nokia N810.*

There was a copy of Pocket in `/usr/local/share/n810-pocket` and another in `/home/nokia/pocket/current`. Under home we also found old releases, experimental Mesa libraries and the remains of individual GPU tests. Which one should go into the installer for the second tablet? The directory called `current` sounded promising. Then we followed the graphics launcher. It selected a release somewhere else entirely, under `/usr/local/lib/n810-graphics/releases/20261109-6970068`.

The original tablet had accumulated 427 Debian packages. The installer image had 198. Only one package they *shared* differed in version. A package comparison could tell us what Debian had put on the machine. For the things we'd installed by hand, we needed to find out who opened each file.

## Follow one station report back to boot

The APRS receiver collects station reports heard over amateur radio. Its startup path crossed enough of the filesystem to explain why a copy of the application directory would miss it. At boot, `/etc/rc.local` ran the scripts in `/etc/boot.d`. One started a supervisor as root. The supervisor changed user and ran `/home/nokia/n810-aprs-feed.py` as `nokia`. That script imported neighboring Python modules and used local sockets and a station database.

For an agent inspecting the read-only backup, the boot script was a good starting point. Following it showed which receiver ran as `nokia` and where that receiver looked for its modules. We traced the graphics launcher the same way to identify the Mesa library and kernel module used on the original tablet.

## A keyboard test the backup couldn't answer

The kernel lived in flash, outside the filesystems we'd saved. When the second tablet's keyboard failed, we recovered the original kernel source and compiler, changed the root-device selection for the second unit, and checked the identity of the kernel that actually booted. The LM8323 keyboard controller still failed to acknowledge reads over I²C, the bus connecting it to the processor. Its interrupt count stayed at zero. That ruled out the later keyboard patches as the sole cause and left the cause of the keyboard failure open.

## Keep one bootable system while repairing the other

The new SD card holds two Debian root filesystems, A and B, plus a separate partition for persistent data such as maps. One flashed kernel can boot either root. We can try an updated slot, wait for Pocket to start, and then mark that slot good.

We needed both slots on November 17. With sound enabled, Pocket's graphics launcher refused to start. We repaired B, booted it and confirmed the desktop was drawing. Then we booted the repaired A and checked the audio and launcher files on the inactive B partition against it. That left us with more than two copies of a directory named `current`. We knew which copy had booted and what it had done. [Sound and graphics on the second tablet](2026-11-17-pocket-on-the-second-n810.md)
